# 第 23 轮 · 本地上下文分阶段扩容

## 目标与授权
用户认可默认 16K、32K 真机验证后作为可选档位的安排，要求适配。当前 0.8B / 8K IPA 已产出，但尚未收到它消除 L14 的真机反馈；代码适配不代表真机稳定性已获验证。

## 本轮实现
- 正式 MLX 本地默认窗口从 8,192 提升到 16,384 tokens；窗口包括输入和最多 1,024 tokens 回复。
- 请求估算、实际 tokenizer 上限、MLX KV 上限和模型信息说明引用同一策略，禁止仅修改显示或单侧预算。
- 保持 512 tokens 估算安全余量、工具查询结果预留、历史摘要与按需查询；不额外塞入每日原始记录，不添加问候精简路径。
- 保持角色、历史、工具完整性和写入确认机制；保留 L14 停机与诊断，不静默转云端或失败后自动扩大窗口。
- 云端窗口与独立 Milo Lab 保持原配置，模型文件及下载版本不变。
- 仅更新既有模型信息中的容量说明，无新增布局或交互；沿用第 19 / 21 轮已确认 UI。

## 后续 32K
先验收 0.8B 8K 短文字基线，再验证 16K 的长历史、工具及单图。32K 不是本次默认值，也不提前开放用户开关。满足真机内存、首字等待和任务质量验收后，补设置选择的设计稿，确认后实现 32K 可选档位。不得把预算单测当成真机可运行证据。

## 验收
- 16K 完整输入输出边界允许，超出 1 token 拒绝；防负数、零值、整数溢出。
- 超过旧 8K 但不超过新窗口的输入可通过预算检查。
- 设置层使用统一预算，切换云端后恢复云端窗口；历史整理和工具相关回归继续通过。
- 本地测试、iOS CI、真机结果分别记录。本次用户未要求再次提交或打包。
