# 原生质感复查

基准：用户明确要求「跟 iOS 一样，简约、细腻、高级」。本次检查现有设计截图与当前 SwiftUI 源码，没有模拟器/真机截图，不将设计截图当成 App 渲染结果。

## 优先修正

1. **教练页底部操作过重（App）**：CoachChatView 的待确认状态同时显示整行「加入课程表」、整行「不采用」和输入栏。两个按钮加内边距约140pt，再叠输入栏；键盘出现时可阅读区域进一步缩小。确认保留主按钮，拒绝降为轻量操作；编辑输入时收敛确认区，退出输入后恢复，不能丢失草稿。
2. **低频操作过度强调（设计稿）**：设置的「检查模型连接」、趋势的「查看训练记录」、报告的「保存报告」被通用模板放到底部整行橙色按钮。分别回归设置分组、普通导航行及按实际保存行为提供的操作；整行主按钮集中用于开始训练和真正需要确认的提交。App部分页面已采用原生工具栏/表单，不应倒退照搬这些模板。
3. **卡片和说明层级重复（设计稿及部分App页面）**：洞察/报告多处采用标题、解释句、卡片再标题的组合；ReportDetailView 还将标题和整段正文分别装卡。去掉重复解释，正文直接排版，卡片用于结构化数据和可操作项目。
4. **次级按钮与主按钮接近同等视觉分量（App共享样式）**：SecondaryButtonStyle 固定整行、填充背景且接近主按钮高度。在拒绝/返回等低优先级场景改用文字操作或系统工具栏；保留44pt可点击区域，减少视觉体积。

## 保留

课程优先、中性聊天气泡、默认折叠思考、可读的橙底深字、系统语义字体、原生设置/编辑表单、真实数据和错误状态。

- [ ] 按操作重要性区分主按钮、文字按钮和导航行。
- [ ] 精简报告/洞察的容器与重复说明。
- [ ] 真机检查深浅、动态字体、键盘/转场/滚动；当前尚不能确认细腻程度。

原生材质使用应服务于层级：Apple HIG 将 Liquid Glass 定位在导航与控制层，避免用于内容层。不能为追求质感给所有卡片添加玻璃效果。参考：https://developer.apple.com/design/human-interface-guidelines/materials
