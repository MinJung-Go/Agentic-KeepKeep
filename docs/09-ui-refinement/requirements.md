- 分支：`feat/ui-refinement`
- 基线：`bb9977a8b22df40fae0e6c0b25a7f291828bb91b`，包含已合并的教练上下文管理。
- 状态：先制作设计稿；32屏设计已获用户确认，SwiftUI 已实施，构建与271个测试通过，运行时视觉验收待完成（见 checklist）。
- 依据：对 [04 轮设计稿](../04-ui-polish/design.html) 的 17 屏浏览器视觉 review，以及用户要求新分支重点优化 UI。
- 清单：[checklist.md](checklist.md)。用户已授权生成真机验证 IPA；预览标签 v0.4.2-ui-preview.1，暂不合并 main。

## 目标与边界

改善信息优先级、阅读对比、卡片密度和主要操作的可见性。先修裁切与图标问题，再改善首页、教练对话与数据图表。

视觉 review 的观察对象是 HTML 设计稿，不能直接认定当前 SwiftUI App 存在相同缺陷。实施时逐项对照实际组件；已在 06/07/08 轮修好的功能只做回归。新版设计稿放本轮目录，04 轮稿保留为对照基线。

本轮不扩展 AI 协议、上下文算法、数据模型或训练业务。沿用 [04 轮设计系统](../04-ui-polish/design-system.md) 的语义色、字号层级和触控尺寸；若配色规范需要修订，同步记录原因和新取值。

## FR1 主要操作与导航可见性

- 记录确认与教练计划内容允许滚动；输入栏、安全区和键盘不裁切确认操作。
- 深浅色图标使用主题语义色，修复设计稿中写死黑色描边的列表、箭头与拖动手柄。
- 每个状态只突出主要操作；停止生成继续只保留一个入口。

验收：短内容、长计划、附图记录下确认操作可达；教练页输入聚焦时收起确认区，点击键盘工具栏「完成输入」后恢复确认，草稿不丢失。两种主题下导航图标清楚可见。

## FR2 首页信息优先级

- 今日课程与开始/继续训练提前，降低概览和健康指标对首屏的占用。
- 健康信息先展示精简摘要，详细指标可展开或进入详情；异常状态和健康授权入口仍可见。
- 记录输入栏保持实底和清楚边界；照片附件与一次发送行为不回退。

验收：常见手机尺寸下首屏可以辨认今日课程及主要操作；无计划、无健康授权、已有训练进度的状态均有明确下一步。

## FR3 文字与配色

- 调整橙底文字搭配，比较深色文字或更深背景的实际效果，避免白字发虚。
- 浅色模式的日期、数量、图例、输入提示和次级说明提高对比。
- 状态同时使用文字/符号表达，避免仅靠颜色区分。

验收：深浅色截图逐项比较正文、辅助信息、选中/禁用态；放大字体后不因固定高度丢字。具体颜色以渲染结果确定。

## FR4 教练与计划卡

- 正式答案成为阅读重点；正文出现后思考区收起，仍可主动展开回看。
- 计划中的动作、组次按整齐的行布局表达，减少重复胶囊、标签与装饰色条。
- 确认后保留计划与回执，已确认/未采用/待确认状态明确，不因视觉调整重复执行计划。

验收：生成中、完成、停止、失败和已确认计划均有视觉样本；长回复与长计划可完整浏览。

## FR5 图表与品牌

- 趋势图提高曲线、图例与日期的可读性，补充必要数值刻度或端点标签；当前指标重点突出。
- 引导页沿用已有黑橙壶铃/勾号品牌资产，加入输入到记录卡的简明示例，改善大面积空白。
- 不把通用哑铃占位符当作最终品牌 Logo，也不重新制作已经具备的 App 图标。

验收：曲线可区分、数值含义清楚；无数据与少量数据状态不误导；引导页与现有 App 图标有一致识别。

## 验证方式

新版 HTML 用浏览器检查 17 屏的首屏、滚动底部及深浅主题，截图留在本轮目录。SwiftUI 对照实际实现，再做适用的构建/回归测试。纯颜色和间距调整不编写镜像实现的单测；涉及状态或操作逻辑时覆盖行为回归。

浏览器截图不能替代 iOS 真机体验；键盘、动态字体、滚动与安全区在具备设备/模拟器条件时复验，并记录实际完成情况。此前 271 个测试通过仅是 main 基线，不能记为本轮 UI 验收。

沿用已确认六屏，覆盖原稿全部 16 类界面，每类深浅两套，共 32 屏。本地独立 HTML 与 Figma 同步交付；仅制作设计稿，新增页面按钮为操作意图示意，不实现 App 业务。
