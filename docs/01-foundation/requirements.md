# Agentic-KeepKeep 需求文档

- 日期：2026-09-11
- 状态：草案（需求确认中）
- 平台：iOS（SwiftUI 原生）

## 1. 项目定位

一款 **Agentic 健身记录与分析应用**：用户用自然语言一句话完成训练/饮食记录，AI 负责解析、归档、分析，并像私教一样生成与动态调整课程表。

### 与 Keep / Apple Fitness+ 的差异

| 维度 | 现有产品 | 本应用 |
|------|---------|--------|
| 记录方式 | 点选表单，繁琐 | 自然语言一句话，LLM 结构化解析 |
| 分析 | 静态图表 | AI 跨维度关联分析（训练×睡眠×饮食），主动发现瓶颈 |
| 课程表 | 固定模板课程 | 根据个人数据动态生成、按反馈调整 |
| 数据归属 | 厂商云 | 本地 SwiftData，BYOK 直连 LLM，无中间服务器 |

## 2. 目标用户

- 首要：开发者本人（个人使用驱动开发）
- 次要：有一定训练习惯、愿意为数据隐私和可定制性自配 API Key 的开源用户

## 3. 发布形态与约束

- **开源 + 个人使用**，上架商业化不在本期范围
- **BYOK**（Bring Your Own Key）：用户自填 Claude / OpenAI 兼容端点的 API Key，Keychain 存储
- 无自建服务器；数据不出设备，除发给 LLM 的聚合摘要外
- 开发资源：个人业余时间，AI 辅助开发

## 4. 功能需求

### P0 — MVP（核心闭环：记录 → 存储 → 分析）

| 编号 | 需求 | 说明 |
|------|------|------|
| F1 | 自然语言记录 | 输入「深蹲100kg 5×5」「中午吃了牛肉面」，LLM 解析为结构化数据（动作/重量/组数/次数；食物/分量/热量）存入 SwiftData |
| F2 | 解析降级 | LLM 解析失败时保留原文为 RawNote，不丢数据，可事后手动修正 |
| F3 | HealthKit 只读接入 | 自动拉取睡眠、HRV、静息心率、步数，聚合为每日 HealthSnapshot；不回写 |
| F3a | iOS 运动记录读取 | 读取 HealthKit 中的运动记录（HKWorkout）：Apple Watch 训练、第三方健身 App 写入的运动，自动归入训练数据，避免重复手动记录 |
| F4 | 手动快捷表单 | 解析结果的确认/编辑界面（卡片式，点选修正数值），同时作为无网时的备用录入 |
| F5 | 今日视图 | 当天的训练、饮食、健康快照、课程表待办汇总 |
| F6 | AI 周/月报 | 基于本地聚合摘要（非原始数据）生成趋势分析：渐进超负荷、平台期、训练-睡眠-饮食关联；报告持久化可回看 |
| F7 | LLM 设置 | BYOK：API Key（Keychain）、主模型默认 **GLM-5.3-Flash**（OpenAI 兼容协议），可切换其他兼容端点（Claude / OpenAI 等）、用量统计 |

### P1 — 私教能力

| 编号 | 需求 | 说明 |
|------|------|------|
| F8 | 对话式课程表创建 | 与 CoachAgent 对话说明目标（增肌/减脂/备赛）、可用器械、每周训练天数；CoachAgent 通过 **function call** 输出结构化 Plan，用户确认后写入课程表 |
| F8a | 对话界面 | CoachAgent 的聊天界面：多轮对话澄清需求，function call 结果以卡片预览呈现，确认/修改后入库 |
| F9 | 课程表调整（双通道） | ① 手动编辑：用户直接增删改 PlanDay（动作、负荷、日期）；② Agent 调整：根据完成记录 + 身体数据（睡眠/HRV/主观反馈）提出修改建议，用户确认后生效；两种通道改动都记录历史 |
| F10 | 饮食分析 | 按日/周聚合热量与宏营养素，结合训练目标给出缺口与建议 |

### P2 — 多模态与增强

| 编号 | 需求 | 说明 |
|------|------|------|
| F11 | 食物照片热量分析 | 拍照/相册上传，VisionAgent 估算食物构成与热量，结果进 MealEntry（标注来源为照片，可人工修正） |
| F12 | 趋势图表 | 体重、1RM 估算、训练量、睡眠等时间序列图表 |
| F13 | 桌面小组件 | 今日待办训练 + 快速记录入口 |

### 明确不做（本期 Out of Scope）

- 社交/社区/好友对战
- 摄像头动作姿态纠正（CoreML 姿态识别）
- 服务端同步、多设备云备份（后续可考虑 iCloud）
- 饮食数据库自建（依赖 LLM 常识估算 + 用户修正）
- Apple Watch 独立 App（只读其 HealthKit 数据）
- Android

## 5. 非功能需求

- **隐私**：API Key 存 Keychain；发给 LLM 的只有聚合摘要，原始记录不出设备；开源代码可审计
- **离线**：记录（降级为 RawNote）、查看、图表完全离线可用；仅 AI 解析/分析需联网
- **成本**：单次解析调用控制在低 token 消耗；分析报告基于摘要而非全量数据
- **可测试性**：Agent 层为纯逻辑（输入数据摘要 + prompt → Codable JSON），不依赖 UI/数据库，可单元测试

## 6. 数据模型（概要）

```
WorkoutSession ─┬─ [ExerciseSet]  动作/重量/次数/RPE
MealEntry      ─┬─ [FoodItem]     食物/分量/热量/宏营养素  来源(文字|照片)
BodyMetric      体重/体脂/腰围（时间序列）
Plan           ─┬─ [PlanDay]      课程表，含状态(待做/完成/跳过)
HealthSnapshot  每日聚合：睡眠/HRV/静息心率/步数 ← HealthKit
AnalysisReport  AI 生成的周/月报（持久化）
RawNote         自然语言原文（解析失败也留存）
```

## 7. 架构决策（已确认）

- SwiftUI 原生 + SwiftData（唯一数据源）+ HealthKit 只读桥接（健康指标 + HKWorkout 运动记录）
- Agent 层四个 Agent：ParserAgent（解析）、CoachAgent（对话 + function call 生成/调整课程表）、AnalystAgent（分析）、VisionAgent（图片热量）
- LLM 抽象层统一协议，BYOK；主模型 GLM-5.3-Flash（OpenAI 兼容协议，支持 function calling），可切换 Claude / OpenAI 兼容端点

## 8. 实施顺序

架构一次设计，实现按 P0 → P1 → P2 推进，每阶段交付可用产品：

1. **P0**：数据模型 + 自然语言记录闭环 + HealthKit + 周报
2. **P1**：课程表生成与动态调整 + 饮食分析
3. **P2**：照片热量 + 图表 + 小组件

## 9. 成功标准（个人使用验证）

- 日常记录单次耗时 < 10 秒，连续使用 4 周不弃用
- AI 周报至少产生 1 条「人工未察觉但认同」的洞察
- 课程表调整建议符合主观疲劳感受的比例 > 70%
