# 第 21 轮 · 正式 App 迁移 MLX

## 基线
用户反馈 Milo Lab 0.1.0 (1) 真机验证通过，授权建立正式需求、清单并开发。该反馈证明独立短文本路径可用，不代表图文、真实长上下文、工具循环已验收。

## 目标与范围
- R1：正式 Moveliq 使用已验证的 MLX Swift 0.31.3 / MLX Swift LM 2.31.3，保留原 Bundle ID、SwiftData、设置及云端配置。正式目标不再链接 llama.cpp，独立 Lab 保留作诊断基线。
- R2：模型默认从 ModelScope 下载，固定 MLX revision、文件大小和 SHA-256。沿用正式 App 的后台下载、暂停恢复、蜂窝选择和校验 UI；不同格式的安装目录与就绪标记必须隔离。旧 GGUF 不自动删除，不误判可供 MLX 使用；旧后台任务不得污染新安装。
- R3：实现 LLMClient 适配，覆盖聊天、记录解析、分析与工具输出；继续使用已校验的白名单／参数验证、写入确认和查询隐私边界。不得因本地失败自动调用云端。
- R4：真机已通过 2K 短文本基线；正式工具上下文保留 8K 上限、最多 1024 输出，prefill 64，缓存 16 MiB。8K 与图文是本轮新增验证范围，不属于既有通过结论。先实际 tokenizer 计数再生成，为输出保留预算；超限给出明确错误，不静默删除用户输入或截断写入提案。正式工具提示词较长，预算适配及实际可用性必须单独验证，不把短文本成功视为全功能可用。
- R5：所有 Agent 共用串行推理通道；每请求释放模型及 MLX 缓存。取消／后台／内存警告保留首因；取消等待底层计算退出，不允许同时加载第二份模型。非思考输出、流式正文不泄露工具标签；结构化输出失败保留原始记录。
- R6：用户确认本轮同时接入并验证图文；单张照片缩放至最长边 384，VLM 路径独立于纯文字。未通过真机验证的视觉能力不得宣称稳定。保留照片原始输入及明确失败路径，图文不会静默外发。
- R7：沿用第 19 轮已确认的布局和交互；模型名称、体积与能力说明随实现同步。若新增迁移界面，先出稿确认，再开发该界面。

## 验收
1. 不影响既有云端、记录、健康与课程表；旧模型不误报就绪，新版可后台下载全部文件。
2. 文字和工具消息按同一模板生成，tokenizer 预算覆盖特殊标记；取消后可再次请求，无双模型驻留。
3. 工具只经原有校验器执行；JSON 不完整或无效时不写入；模型错误不导致原记录丢失。
4. 纯逻辑测试、模型清单／安装状态测试和既有回归；Apple SDK 构建、工具任务质量、图文与真机性能分开记录。

## 交付
需求、checklist、正式 App 适配、迁移测试与证据。用户已追加授权开发后提交、推送并打包 IPA。
