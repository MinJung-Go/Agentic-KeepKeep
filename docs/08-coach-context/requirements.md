## 1. 问题与实施前现状

实施前 `CoachChatView.send()` 读取全部用户消息与有正文的助手消息，`CoachAgent.buildMessages()` 将其完整加入每次请求，没有输入预算、历史压缩或超限恢复。聊得越久，请求越大，最终可能被服务端拒绝。

个人训练/健康数据已有近 28 天概况与近 14 天简要摘要，但这是业务数据聚合，不是聊天历史压缩；代码注释中的“约 300 token”也不是严格预算。思考过程未作为历史回传。计划与调整工具结果没有进入历史文本：助手只输出卡片时，该消息会被过滤；已确认的计划在聊天中虽有回执，教练上下文中的课程表仍主要是标题和完成进度。

## 2. 目标

1. 发出的请求规模受预算约束，不随聊天历史无限增长。
2. 保留用户训练目标、器械条件、时间安排、伤病/动作限制及当前计划，减少长对话后的遗忘与矛盾。
3. 首页/记录功能和教练流式体验保持原有职责；用户无需手动清空聊天来处理常见超限。
4. 本地完整聊天仍可回看；摘要只用于构造模型上下文，不删除或改写原始消息。

## 3. 功能需求与验收

### FR1 请求预算

- 发送前统一计算系统指令、业务概况、记忆、近期消息、本轮输入及工具定义的输入占用。
- 根据模型配置预留真实输出上限和安全余量；思考预算按协议与请求参数计入，不能只统计可见正文。
- 输入预算为 `min(App 输入上限, 模型窗口 - 输出预留 - 安全余量)`；预算无效时提前提示，不发送已知无法容纳的请求。
- 提供可替换的 token 估算接口。启发式估算必须标明误差并保留余量，不能声称等同服务端 tokenizer。
- 自定义端点/未知模型采用可配置的保守窗口假设，不能仅凭模型名猜测无限窗口。切换模型或端点后重新计算预算。
- 当前用户输入和必要固定内容本身超预算时，保留原文、提示拆分或调整配置，不静默截断用户输入。

**验收**：短请求不压缩；预算边界内外的行为可重复测试；系统、工具、输出/思考预留均影响结果；组装完成后再校验一次总预算。文档明确估算预算与服务端真实窗口的区别。

### FR2 近期对话与较早对话摘要

- 保留近期完整对话轮次，较早历史按需压缩成有长度上限的摘要；轮数是保留目标，token 预算优先。
- 按完整轮次裁剪，避免将助手回答与对应问题随意拆开；本轮输入只加入一次。
- 摘要请求自身也必须受预算约束。历史很长时分段、增量处理，不把全部历史再塞进一次摘要请求。
- 摘要记录已覆盖消息范围和版本，只有新历史越过压缩边界时才增量更新，不能每次发送都重新总结。
- 摘要保留目标、偏好、限制、用户纠正、未解决问题与关键决定；区分“用户明确说过”与“模型建议”，不得将推测固化为事实。
- 用户最新明确纠正优先；保留限制的来源和时间，不因摘要刷新悄悄消除伤病等重要约束。摘要不是医疗诊断。
- 原始思考过程不参与摘要；摘要被当作历史资料，不得覆盖系统指令或授予执行工具的权限。

**验收**：10/100/500 轮合成历史均满足估算预算；反复发送不重复摘要已覆盖内容；用户新旧目标冲突时采用最新明确表述；摘要不得虚构器械、伤病或已确认操作。

### FR3 计划与工具结果记忆

- 已生效计划与完成状态以 SwiftData 当前数据为准；聊天摘要不得覆盖数据库中的最新修改。
- 对计划卡片及调整结果构造有预算的结构化摘要，覆盖助手没有正文、只返回工具卡片的情况。
- 明确区分待确认草稿、已确认计划、被拒绝/已替换计划；不得将待确认建议描述成已执行。
- 保留与当前问题相关的训练日、动作、组次和重量；较大课程表按预算筛选相关部分，并标明省略范围。
- 相对日期要结合消息/确认时间解析，不能把多天前的“今天”当成当前日期。
- 不为记忆而重复调用创建/调整计划工具，继续遵守用户确认后才落库的规则。

**验收**：计划卡片无正文、确认后继续追问、在课程表编辑计划及替换激活计划后，教练收到的状态正确；压缩/重试不创建额外计划。

### FR4 持久化与生命周期

- 记忆保存在本地 SwiftData，与所属聊天会话及覆盖消息范围关联；原始聊天是可重新生成摘要的依据。
- 旧安装升级时没有记忆也能正常工作；摘要结构升级需有版本与失效策略，不将数据库迁移失败作为正常流程。
- 只有摘要成功、结构有效且来源会话仍有效时才提交缓存；取消、失败或过期异步任务不得写入半成品。
- 清空聊天同时清空记忆并使在途任务失效，防止旧请求完成后“复活”已清除内容。
- 切换模型重新估算预算；同一用户同一聊天的记忆不必无条件丢弃，但必须重新校验兼容性与长度。

**验收**：重启后复用有效摘要；清空后不残留或重建旧记忆；在途清空/停止、失败更新及旧数据库迁移有覆盖测试。

### FR5 超限恢复与失败处理

- 识别明确的上下文超限错误；缩减历史后最多自动重试一次，重试仍须重新校验预算。
- 只有尚未展示回复且未产生可用工具结果时允许自动重试，避免输出重复、工具重复或用户看到两份回复。
- 鉴权、额度、限流、一般网络错误及无关的 400 错误不得当成上下文超限重试。
- 摘要失败时优先保留上次有效记忆与必要约束，尝试使用预算内近期历史；无法安全装入必要内容时保留输入并提示，不默默丢弃关键限制。
- 区分输入超限与输出被截断，不能把未完成工具 JSON 当成完整计划执行。
- 用户停止生成要同时停止摘要和回复过程；同一次用户发送只产生一条用户消息。

**验收**：超限→压缩→成功只有一次补偿请求；再次超限、鉴权失败、摘要失败、部分输出后失败和用户取消均有明确结果；无无限重试或重复消息。

### FR6 交互、用量与隐私

- 需要整理上下文时用简短状态提示“正在整理聊天记录…”；可停止，完成后自然进入现有流式回复。
- 短对话不增加额外摘要调用；长对话复用缓存，摘要调用纳入现有用量统计。
- 摘要仅使用已有教练聊天与业务聚合信息，继续使用用户配置的服务商，不新增第三方服务或上传原始健康记录。
- 日志只记录估算量、裁剪轮次、摘要/重试耗时等诊断信息，不写原始聊天、健康内容或 API Key。
- 普通聊天界面不堆叠 token、模型窗口等实现参数；只有用户处理配置问题时才提供必要信息。

**验收**：可停止整理与生成；摘要费用有统计；本地聊天不因压缩减少；通过日志检查和请求快照验证数据边界。

## 4. 实施起点与待校准参数

建议按“预算规划 → 本地记忆/摘要 → 计划状态 → 超限恢复 → 界面与验证”分批实现。

近期保留目标可从 6 轮、记忆上限可从 1,500 个估算 token 起步，但均是待测试的工程候选值，不是模型规格或硬性保证。模型窗口回退值、默认输入上限、输出/思考预留、安全余量与摘要触发阈值，需在实现预算模块时结合现有请求配置及中英文/长工具样本确定并写入测试；不得散落为多个互不一致的常量。

设计边界：Agent 层继续保持纯逻辑、可注入客户端，不直接操作 SwiftData；持久化与异步任务协调由数据/功能层负责。流式与非流式教练入口复用同一预算策略，避免某条路径绕过限制。

## 5. 非功能要求

- 长历史处理避免主线程上反复全量拼接与估算；摘要增量更新，长任务可取消。
- 兼容现有 OpenAI 兼容协议和 Anthropic 协议，不依赖单一服务商的专属自动压缩 API。
- 测试不调用真实付费接口，使用注入客户端和合成数据；真实模型的记忆质量、延迟与费用另行记录，不能仅凭单测声称已验证。
- 旧聊天、已确认计划回执与数据迁移必须可回归验证。

## 6. 本轮范围外

不引入向量数据库/RAG、跨设备记忆同步、多用户账户体系或无限上下文承诺；不扩大到 Parser/Vision/Analyst 的历史管理；不实现自动换服务商、自动换模型或无界重试。本次按用户后续指令实现并合并 main，不进行版本发布或 IPA 打包。

## 7. 本轮落地参数

参数与保护策略见 [verification.md](verification.md)。本轮采用带消息来源的逐字引用记忆，而非自由改写摘要；用户引用不可在刷新时静默删除，模型返回的每条引用必须能在对应原文中找到。显式限制/纠正另有原文行保留保护。若必要记忆超过容量，安全失败并保留聊天，而非承诺任意长会话都能继续压缩。
