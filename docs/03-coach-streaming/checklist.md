# 教练上下文 / 流式回复 / 图片与文字同发 Checklist

- 日期：2026-09-12
- 分支：`feat/coach-streaming-and-context`
- 来源：真机使用后的第二轮反馈（3 条）
- 验证方式：GitHub Actions 构建 + 单测（本机无 Mac，UI 效果需装机确认）

## 问题与方案

### 1. 教练对话希望综合所有个人信息来回复

**现状**：`CoachContext.recentSummary` 只有一行（「近 14 天训练 6 次，日均睡眠 6.4h」），
教练看不到训练细节、恢复趋势、饮食缺口、体重变化和课程表进度，回复自然泛泛。

**方案**：新增 `CoachContextBuilder`，把本地聚合结果拼成一份**结构化个人概况**注入 system prompt。

- [x] 训练：次数、总容量、主要动作的最佳/最近 e1RM 与停滞周数（复用 `DataAggregator.digest`）
- [x] 恢复：日均与最低睡眠、HRV 日均、静息心率（对应「恢复」诉求）
- [x] 饮食：记录天数、日均热量与三大营养素、蛋白质目标缺口（复用 `NutritionAnalysis`）
- [x] 身体：体重最近值与区间变化
- [x] 课程表：当前计划名、完成进度、距上次训练天数（「今天/昨天/N 天前」）
- [x] 提示词：要求教练在给建议时**引用这些数据**，恢复不足时主动建议减载
- [x] 对话界面顶部展示「已参考你的近期数据」，可展开查看（保持 AI 透明）
- [x] 概况控制长度（分段拼接，约 300 token 内），避免每轮对话成本膨胀

### 2. 教练回复改为流式，并显示思考内容（如 Kimi）

**现状**：`complete()` 一次性返回，长回复要等十几秒；模型返回的 `reasoning_content` 被忽略。

**方案**：LLM 层增加流式接口，UI 边收边渲染，思考内容折叠展示。

- [x] `LLMStreamEvent`：`reasoning` / `text` / `toolCall` / `usage` / `finished`
- [x] `LLMClient.stream(_:)` + 协议默认实现（不支持流式的客户端自动退化为一次性）
- [x] OpenAI 兼容客户端实现 SSE：解析 `data:` 行、`[DONE]`、增量累积 tool_calls（含参数分片拼接）
- [x] 识别 `reasoning_content`（智谱 GLM / Kimi / DeepSeek 同字段）与 `reasoning`
- [x] Anthropic 客户端实现 SSE（`content_block_delta`、`thinking_delta`、`input_json_delta`）
- [x] 请求侧支持开启思考：GLM 走 `thinking: {type: enabled}`；Claude 走 `thinking + budget_tokens`
      （此时省略 temperature 并把 max_tokens 提到 4096）
- [x] 设置项：「显示思考过程」开关（默认开，不支持的模型可关掉）
- [x] `ChatMessage` 增加 `reasoningText` 字段，历史消息也能回看思考
- [x] 对话 UI：思考区流式中展开、结束后折叠；正文逐字追加；失败时保留已收到的内容
- [x] 流式期间发送按钮变「停止」（可中断）
- [x] 记录解析仍用非流式（结果以卡片呈现，逐字反而干扰）

**实现要点**：OpenAI 与 Anthropic 的拼接逻辑抽成共享的 `LLMStreamAccumulator`，
避免两份实现分歧；用量分两次上报时**合并**而不是覆盖（Anthropic 先给输入、后给输出）。

### 3. 选图就立刻分析不对，应该支持配文字一起发

**现状**：`PhotosPicker` 选中照片后立刻调用视觉模型，用户没有机会补充说明（「这是午饭，大约一碗」），
也不能只发文字。

**方案**：照片改为**附件**，与文字一起在用户点「发送」时才处理。

- [x] 选图后仅附加：显示缩略图 + 「可再补一句说明，然后发送」，不触发分析
- [x] 发送条件：有文字**或**有照片即可发送
- [x] 只发文字 → `ParserAgent`；只发照片 → `VisionAgent`；图文同发 → `VisionAgent` 带上文字作为补充说明
- [x] 发送后清空输入与附件；用户气泡显示相机图标表示带图
- [x] 保留失败降级（RawNote）与错误分类提示
- [x] `VisionAgent.analyzeMeal` 的 `note` 参数接上用户文字

## 真机复验要点

1. **流式**：教练回复应当逐字出现；先出现「思考中…」，正文随后逐字追加；发送按钮变「停止」
2. **思考内容**：若模型支持，会显示折叠的思考块。若看不到，检查「设置 → 显示思考过程」是否开启，
   以及当前模型是否支持（GLM/Kimi/Claude 支持；部分小模型不支持，可能因此报错——遇到报错就关掉该开关）
3. **个人数据**：对话顶部应有「已参考你的近期数据」，展开能看到训练/恢复/饮食/身体/课程表
4. **图片**：选图后**不应**立刻分析，应显示缩略图等待发送；补一句「大约一碗」再发，估算应更准

## 遗留

- 流式的 token 用量：GLM 未确认支持 `stream_options.include_usage`，因此教练流式调用的用量可能不计入统计
  （OpenAI 端点已启用）。若在意，可在设置里查看「累计用量」时注意这一点。

## 风险与取舍

- 流式 + function calling 需要跨 chunk 拼接工具参数，若模型分片异常需回退到非流式重试
- 思考内容字段各服务商命名不一（`reasoning_content` / `reasoning` / `thinking`），只做「有就显示」
- 个人概况进入 prompt 会略微增加每轮 token 成本，用长度上限约束
