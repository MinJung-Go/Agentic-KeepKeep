# 教练综合个人数据 / 流式回复 / 图片与文字同发 —— 需求文档

- 日期：2026-09-12
- 状态：已实现并验证（**本文档为事后补写**，用于补齐该轮需求基线；内容与实施结果一致）
- 分支：`feat/coach-streaming-and-context` → PR #2（合并提交 `1183c60`）
- 实施与验证：[checklist.md](checklist.md)

## 1. 背景

使用者在真机（v0.1.1）上用过一轮后提出三条问题：

1. 和 AI 教练对话时，它看不到我的训练、恢复、饮食、体重与课程表，回复很泛
2. 期望教练回复是流式的，并且能看到思考内容（类似 Kimi 的深度思考展示）
3. 记录时选中照片就立刻触发分析，没有机会补充说明（如「大约一碗」），也不能只发文字

## 2. 目标

- 教练的建议要**基于使用者的真实数据**，能引用具体数字，而不是通用健身常识
- 对话体验接近主流 AI 对话产品：逐字输出、可看思考、可中断
- 记录的输入方式更自然：照片是附件，可配文字，由使用者决定何时发送

## 3. 功能需求

### FR1 教练综合个人数据

| 项 | 要求 |
|----|------|
| FR1.1 | 聚合训练数据：近 N 天训练次数、总容量、主要动作的最佳/最近估算 1RM 与停滞周数 |
| FR1.2 | 聚合恢复数据：日均与最低睡眠、HRV 日均、静息心率 |
| FR1.3 | 聚合饮食数据：记录天数、日均热量与三大营养素、蛋白质目标缺口（目标 = 体重 × 1.6g/kg） |
| FR1.4 | 聚合身体数据：最新体重与区间变化 |
| FR1.5 | 聚合课程表：当前计划名、完成进度、距上次训练天数 |
| FR1.6 | 以上内容注入 system prompt，并要求模型**引用具体数字**；恢复不足时优先建议减载 |
| FR1.7 | 界面展示「已参考你的近期数据」并可展开核对，保持 AI 透明 |

**验收标准**：概况文本包含五段（训练/恢复/饮食/身体/课程表），缺失数据的分段自动省略；长度控制在约 300 token 内。

### FR2 流式回复与思考内容

| 项 | 要求 |
|----|------|
| FR2.1 | 支持流式输出：正文逐字追加渲染 |
| FR2.2 | 支持思考内容：识别 `reasoning_content`（GLM/Kimi/DeepSeek）与 Anthropic 的 `thinking_delta` |
| FR2.3 | 思考区在生成中展开、结束后折叠；历史消息可回看 |
| FR2.4 | 流式期间可「停止生成」；中断时保留已收到的内容并落库 |
| FR2.5 | 支持 function call 的流式解析（工具参数跨分片拼接） |
| FR2.6 | 设置项「显示思考过程」，不支持的模型可关闭（避免服务商报错） |
| FR2.7 | 记录解析（ParserAgent / VisionAgent）保持非流式：结果以卡片呈现，逐字反而干扰 |

**验收标准**：OpenAI 兼容与 Anthropic 两种协议均能流式；空回复报错；工具调用在流结束时给出完整参数。

### FR3 照片作为附件

| 项 | 要求 |
|----|------|
| FR3.1 | 选图后仅附加，显示缩略图与提示，不触发分析 |
| FR3.2 | 有文字**或**有照片即可发送 |
| FR3.3 | 只文字 → 文本解析；只照片 → 视觉识别；图文同发 → 文字作为视觉识别的补充说明 |
| FR3.4 | 发送后清空输入与附件；用户消息显示相机图标 |
| FR3.5 | 失败分类提示（模型不支持图片 / Key 无效 / 额度不足 / 网络） |

## 4. 非功能需求

- **隐私**：注入教练的只有聚合结果，逐条原始记录不出设备；界面可查看注入了什么
- **成本**：个人概况限制长度；只在教练对话启用流式
- **兼容**：不支持的客户端/模型自动退化（无流式 → 一次性；无思考 → 不显示思考区）
- **可测试性**：流式拼接、概况聚合、教练流式调度均需单测覆盖

## 5. 明确不做

- 不做逐字输出的**记录解析**（只做教练对话）
- 不做对话历史的服务端存储或跨设备同步
- 不做模型自动降级（思考开关由用户控制，不自动探测模型能力）
- 不做照片的多图上传（一次一张）

## 6. 风险与遗留

- **流式未经真实接口验证**：拼接逻辑由单测覆盖，但未对 GLM/Kimi 的真实 SSE 响应做过端到端验证
- **思考参数差异**：GLM 用 `{thinking:{type:enabled}}`，Claude 用 `thinking+budget_tokens`；不支持的模型可能返回 400，需用户关闭开关
- **用量统计**：`stream_options.include_usage` 仅在 OpenAI 端点启用，GLM 的流式调用可能不计入 token 统计
