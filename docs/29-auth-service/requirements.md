## 已确认范围

- 服务放在外部独立 GitHub 仓库，名称 `Moveliq-Service`（独立 GitHub 私有仓库已创建并推送功能分支），后续支持 Vercel 或自有服务器部署。服务端源码不放入 App 仓库。
- 服务负责账号、会话、邀请及云端模型代理；模型 API Key 只存服务端，App 不要求用户配置供应商密钥。
- 关闭本地模型入口并停止下载、加载，保留源码以便恢复；不删除 MiloInference 仓库或擅自删除已下载权重。

## 邀请码规则

1. 每个邀请码只能成功注册一个账号，不是可使用三次。
2. 邀请码成功消费后，新账号获得恰好 3 个新的一次性邀请码。
3. 每个受邀者注册成功后同样获得 3 个，逐层延续，不设固定裂变层数。
4. 重复登录、刷新列表、注册请求重试不得追加邀请码。
5. 创建用户、消费原邀请码、创建 3 个子邀请码需在一个数据库事务中完成；失败应回滚，不吞码、不产生半注册账号。
6. 同一码并发注册至多一个成功；每个用户的三份初始邀请额度需有数据库唯一约束或等效保证。
7. 子邀请码记录所属用户、来源邀请码及消费状态，关系留在服务端；App 展示可用／已使用状态，不公开受邀者私人信息。
8. 邀请码由服务端安全随机生成，注册校验及尝试次数限制在服务端执行，不相信客户端提交的可用状态。

## App 改动边界

- `RootView` 增加会话入口，`hasCompletedOnboarding` 不代表登录；注册后走引导，已完成引导的登录用户进入首页。
- `KeepKeepApp` 处理模型下载初始化、后台恢复、前后台及内存事件；仅隐藏设置项不足以停用本地模型。
- 迁移旧 `LLMSettings.useLocalModel` 偏好，确保请求不再进入本地推理路径。
- 教练、解析、视觉、报告及网页搜索／阅读均梳理服务端代理路径；保留流式正文、思考、工具调用和用量语义。
- 服务端按会话鉴权，限制可调用模型和上游地址；客户端取消请求时取消上游调用。
- 密码仅存安全哈希；App 的会话凭据存 Keychain，不保存明文登录密码。验证码和邮件不作为账号恢复依赖。
- 服务端账户、会话、邀请码及限流状态需要共享持久化，不能只存在 Vercel 函数内存中。
- SwiftData 按服务地址＋用户 ID 隔离；检测到旧记录时先明确确认归属，直接沿用原库而不搬动或删除。退出清除小组件授权并取消请求，启动需联网恢复会话；当前不提供未登录离线查看。
- 更新 AI 数据说明：请求内容会经自有服务中转，不能继续宣称仅直连用户自有模型。
