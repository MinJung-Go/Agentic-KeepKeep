# 05 · 训练执行页

- 日期：2026-09-14
- 状态：**已确认，实施中**
- 由来：04 轮 FR17 初稿误将「训练执行页」写成本轮交付物，已移出并记为候选（见 [docs/README.md](../README.md)）

**已确认的取舍**（2026-09-14）：

| 决定 | 选择了 | 理由 |
|------|--------|------|
| 逐组记录粒度 | **每组一条 `SetLog`**（FR3.1） | 设计稿画的就是逐组重量×次数；只记「做了几组」的话，第 4 组减重这种情况记不下来，日后还得再改一次模型 |
| 中断恢复 | **落库草稿**（FR5.3 / FR6.2） | 健身房里锁屏、切音乐、接电话都很常见；退出即丢会让人白练一趟 |

## 1. 背景

用户带着计划去健身房，实际会发生两件事：

1. **做到第三组忘了要领** —— 这正是 04 轮做的动作示范图最有价值的时刻，但那一轮的示范图只在「动作详情页」能看到，训练中要退出去翻，打断节奏
2. **练完不知道记了什么** —— 现在训练记录靠事后一句话（「深蹲100kg 5×5」），或者手动一条条补。跟着计划练的时候，组次本来就定好了，没有理由让用户再敲一遍

所以这一轮把「计划」和「记录」之间那条断掉的链路接上：**跟着计划练，逐组打勾，练完自动变成一条训练记录。**

## 2. 目标

- 训练中**一屏之内**看到：当前动作的示范图、组次、要领，并逐组打勾
- 练完**不用重新输入**就能生成结构化记录
- 不做成通用训练 App —— 只服务「有课程表、按计划练」这一条路径

## 3. 功能需求

### FR1 入口

| 项 | 要求 |
|----|------|
| FR1.1 | 今日页的课程卡，主按钮从「标记完成」改为**「开始训练」**（有计划且未完成时） |
| FR1.2 | 课程表 · 单日页底部常驻「开始训练」 |
| FR1.3 | 已完成的训练日照常显示「已完成」，可重开（用于补练） |

**验收**：从今日页两步内进入训练执行页。

### FR2 训练执行页（主界面）

| 项 | 要求 |
|----|------|
| FR2.1 | 顶部：课程主题 + 「结束」；下面一行「第 N / M 个动作」+「已练 X 分钟」 |
| FR2.2 | 当前动作卡：**示范图 140pt**（复用 04 轮的 `ExerciseMediaView`，未下载时给占位）+ 动作名 + 「重量 · 组数×次数」+ 肌群胶囊 + 要领 |
| FR2.3 | 动作名可点，进「动作详情页」看完整说明（不打断流程，返回即回到训练） |
| FR2.4 | 下方逐组列表：每行「第 N 组」+「重量 × 次数」+ 勾选圆点 |
| FR2.5 | 底部主按钮**「完成这组」**：点一下勾掉当前组，自动进入下一组；最后一组做完自动切到下一个动作 |
| FR2.6 | 上一个 / 下一个动作可直接跳（允许跳过某个动作） |

**验收**：一屏放得下示范图 + 组次列表 + 主按钮，不滚动也能完成一组。

### FR3 逐组记录

| 项 | 要求 |
|----|------|
| FR3.1 | 每组一条独立记录（`SetLog`），**默认沿用计划的重量与次数**，打勾即可，不强制输入 |
| FR3.2 | 点某一组可展开改重量 / 次数 —— 用于「第 4 组减重」这类情况 |
| FR3.3 | 实际完成的组与计划不符时（多做/少做），以实际为准写回记录 |

**验收**：不做任何输入也能走完整个流程；想改的时候能改。

### FR4 计时

| 项 | 要求 |
|----|------|
| FR4.1 | 记录开始时间，页面上显示「已练 X 分钟」 |
| FR4.2 | 组间计时**不做** —— 那是另一个功能（见「明确不做」） |

### FR5 结束与写回

| 项 | 要求 |
|----|------|
| FR5.1 | 点「结束」→ 汇总卡：练了多久、几个动作、多少组、总容量 |
| FR5.2 | 确认后生成一条 `WorkoutSession`（含各动作的 `ExerciseSet`），并把该训练日标为已完成 |
| FR5.3 | **中途退出**（返回 / 杀进程）：已打勾的组要留着，下次进来接着练；不生成半截记录 |
| FR5.4 | 一组都没勾就退出：不留任何痕迹，直接丢弃 |

**验收**：练完不用重新输入，记录页里能直接看到这条训练；中途退出再进，勾选状态还在。

### FR6 数据模型变更

| 项 | 要求 |
|----|------|
| FR6.1 | 新增 `SetLog`：`setIndex` / `weightKg` / `reps` / `completedAt` / 反向关系 `planExercise` 或 `set` |
| FR6.2 | 新增 `WorkoutSessionDraft`（进行中的会话）：`planDayID` / `startedAt` / 已完成的组；结束时转成正式记录并删除 |
| FR6.3 | 现有模型只**增字段**、不改语义；旧数据要能平滑打开（轻量迁移） |
| FR6.4 | 现有 208 个单测保持全绿 |

**验收**：装上旧版本产生的数据能正常打开，不丢记录。

### FR7 边界

| 项 | 要求 |
|----|------|
| FR7.1 | 示范图未下载：占位 + 一句「设置 → 动作示范图」，不阻断训练 |
| FR7.2 | 动作未收录：只显示名称与组次（沿用 04 轮 FR17.7） |
| FR7.3 | 计划日没有动作：给一句说明，不给一个空流程 |
| FR7.4 | 计划里只写了「4×10」没写重量：重量留空，不编造 |

## 4. 非功能需求

- **响应**：打勾到下一组就位 < 100ms，不阻塞主线程
- **可测试性**：会话推进（下一组 / 下一动作 / 结束汇总）抽成纯逻辑 `WorkoutSessionEngine`，可独立单测
- **不回归**：不改 Agent 提示词与 function call 契约；不引入第三方依赖
- **离线**：除示范图外全部离线可用

## 5. 明确不做

- **组间计时 / 休息倒计时** —— 是另一个功能，需要通知权限与后台计时
- **自由训练**（不跟计划）—— 现有的一句话记录已经覆盖
- **训练中改计划** —— 改计划回课程表改
- **Apple Watch** —— 本轮不碰
- **社交 / 分享** —— 不做
- **数据模型重构** —— 只增不改（04 轮那条「不改数据模型结构」的约束在这一轮**放开**，但仍以最小改动为限）

## 6. 风险

| 风险 | 说明 |
|------|------|
| **数据模型变更** | 这是本项目第一次改数据模型。SwiftData 的轻量迁移对「加新模型 + 加带默认值的字段」是安全的，但要真机验证旧数据能打开 |
| **中断恢复** | 「杀进程后接着练」需要把草稿落库，多一份状态要考虑清理（过期草稿怎么办） |
| **决策疲劳** | 逐组打勾很容易做成「每一步都要点」。默认值必须足够聪明，能一路点下去 |
| **和现有记录流程打架** | 练完生成的 `WorkoutSession` 与用户手敲的记录走同一个列表，样式要一致 |
