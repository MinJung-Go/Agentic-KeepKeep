# Moveliq 品牌统一与 Milo 首页

状态：用户已确认按设计开发并产出 IPA；已实现并通过 CI，0.4.5 (9) IPA 已生成，待真机验收，暂不同步 Figma。

## 背景与目标

0.4.4 已接入 Milo 角色，但“和 AI 教练聊聊”、旧产品名与壶铃图标仍有残留。本轮统一产品与角色身份，并让用户打开首页即见 Milo，同时保持训练与记录的直接入口。

## R1 · 产品品牌与角色称呼统一

- 产品名统一为 **Moveliq**：桌面显示名称、首次使用、设置、关于、用户可见的导出／安装说明等产品文案保持一致。
- 产品使用独立 Logo，角色使用已认可的 Milo IP；2026-09-16 用户确认替换为淡蓝小糯团、黄色手环、同色六块浅腹肌，产品暖橙强调色保留。当前提供原创 M 字形矢量方向稿，本轮使用此图形。
- 角色默认 **Milo（米洛）**，与第 17 轮自定义昵称联动。“和 AI 教练聊聊”等角色入口改为“和 {昵称} 聊聊”；聊天标题、首页问候身份、角色设置与导航保持一致。
- 昵称为空回退 Milo；长昵称截断展示、完整无障碍标签可读。品牌名 Moveliq 不随角色改名而变化。
- 后续实现需逐项清查主 App、小组件、通知、空态、辅助功能标签等用户可见字符串。历史用户聊天内容不进行批量替换。
- 品牌变更不修改 Bundle ID、App Group 或 Keychain 标识，保留既有安装升级与用户数据；工程内部名称和历史技术文档无需机械替换。

验收：新安装与升级后产品标识一致；自定义昵称后无固定“AI 教练”角色入口；旧数据与配置保留。

## R2 · Milo 作为默认首页

- 默认进入 Milo 首页；底部导航为「Milo（随昵称）／记录／课程表／洞察／设置」。完整聊天和历史对话仍有独立入口，不把长聊天历史铺在首页。
- 首页顺序：Moveliq 品牌与历史对话入口 → Milo 问候与一条简短信息 → 至多两个快捷对话 → 今日训练 → 今日记录 → 常驻统一输入栏。
- Milo 保持适度头像尺寸，内容优先，不用大幅角色插画挤占日常训练区。
- 有计划：提供“开始／继续训练”，展示当天安排；休息日如实显示休息，不能强行安排训练。
- 没计划／首次使用：自然问候，引导创建计划或记第一条记录。没有健康授权、没有数据或离线时，不虚构恢复评价或训练事实。
- 问候可本地生成；个人化信息基于可见记录、注明必要的数据范围，不以每次打开首页的额外模型请求为前提。
- 今日记录显示简短近期条目，更多内容进入记录页；保留课程、记录和洞察原有功能。

验收：有计划时能直接开始训练；无数据时有自然引导；聊天入口可发现；数据缺失不被解释为用户没运动。

## R3 · 统一输入，结果明确

- 首页输入支持文字及照片入口，保留语音能力。空白时弱化发送，输入内容或选择附件后显示发送按钮。
- 明确聊天意图：携带输入进入完整 Milo 对话；明确记录意图：进入可编辑的结构化记录确认；无法确定时，提供“整理为记录／继续对话／返回修改”。不要求每条消息都额外选择。
- 照片与文字一起传递，不丢附件或原文；识别失败保留原始输入与可重试状态，沿用现有 RawNote 降级规则。
- 记录卡片确认前不保存；可编辑动作、重量、组次，取消不产生训练记录。成功后显示回执并更新首页记录。
- 修改课程表仍按第 17 轮先提出草稿、确认后执行；查询记录不自动写入记录，不能静默修改课程表。
- 完整聊天继续使用“思考 → 工具 → 思考”的真实有序过程，放在最终回复上方。
- 输入栏、Tab Bar 与键盘各有安全区域；键盘展开有明确收起入口。保留滚动阅读位置，不用浮层遮挡操作卡片。

验收：普通聊天、纯文字记录、图文记录、意图不明、取消、失败重试分别符合预期；单次确认仅保存一次，不丢原文或附件。

## 后续开发范围

按用户确认的品牌图形和首页层级实施。当前不新增主动通知、永久记忆体系或自动训练决策，不改变 HealthKit 只读与 BYOK 架构。

## R4 · 首次联网与角色身份修正

用户追加确认：新用户进入欢迎页即尝试联网，让适用设备的系统联网授权尽早出现。使用一次短超时、无 API Key／健康数据／聊天内容的 HTTPS HEAD 请求；不调用模型，不等待授权成功才允许继续。记录的是“已尝试”，不是授权状态；已完成引导的老用户不额外触发。系统弹窗受 iOS／地区与已有授权状态控制，不能保证所有设备弹出。

助手的默认身份明确为“你叫 Milo，是 Moveliq 的运动伙伴”。自定义名字属于助手，不属于用户；用户姓名只有本人明确提供时才可使用。保持偏好数据的 JSON 边界、课程修改确认与工具权限规则。

## R5 · Milo 浅深色视觉适配（2026-09-16 设计已确认）

沿用用户确认的小糯团头型、淡蓝身体、黄色手环与同色六块浅腹肌。浅色保持通透感；深色使用炭黑背景 #161719，压低角色发白高光与黄色点缀的亮度，保留暖橙品牌操作色。首页角色维持 78pt，避免用大幅插画挤占内容。

先交付新版四屏稿、同内容浅深并排对照和小尺寸样例；深色角色在 HTML 内用 CSS 调色模拟，确认后再决定正式深色资源的制作与接入。设计已确认并进入 App 实施，不同步 Figma。正式实现使用共享 MiloAvatar 的运行时调色，保留同一素材轮廓；响应系统跟随与手动外观选择，不另存深色 PNG。历史轮次的截图保留。
