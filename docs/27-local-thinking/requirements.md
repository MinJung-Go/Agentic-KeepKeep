# 第 27 轮 · 本地模型思考模式与撞顶保护

## 背景与目标

用户要求打开本地模型的思考模式，并明确要求「输出上限保护（撞顶即中止思考）」。

已核实的事实（2026-09-20）：

- Qwen3.5-0.8B 支持思考，通过 `enable_thinking` 控制；本地锁定的 chat_template 与官方模板 SHA-256 完全一致，含 `enable_thinking=true` 分支（渲染 `<think>\n` 开块，模型自行输出 `</think>` 结束）。
- 官方警告：Qwen3.5-0.8B 思考模式下比其他 Qwen3.5 更容易陷入思考循环，建议流式监控并及时中断；推荐采样参数为 temperature 1.0 / top_p 0.95 / presence_penalty 1.5（VL 任务 0.6）。
- 本地模板**没有** `thinking_budget`（仅 DashScope API 有），「预算内自动收尾」不可用，只能由 App 侧监控与中止。
- 底层 mlx-swift-lm `GenerateParameters` 支持 topP/topK/presencePenalty；私有推理包的 `InferenceRequest` 目前只暴露 temperature。
- 设置页已有「深度思考」开关（`llm.thinkingEnabled`，默认开，现仅云端生效）；LLM 层已有 `reasoning` 流式事件与聊天页思考展示、工具活动 thinking 状态。

## 范围（已确认 2026-09-20）

- 思考开启走**文字路径**（App 全量可控）；图文（VLM）路径需改私有包传 `enable_thinking`，本轮不做，列为后续。
- 本地思考接入现有「深度思考」开关，**默认开**（与现开关一致）；`LocalPrompt.render` 读取 `request.thinkingEnabled` 渲染开块；解析层按首个 `</think>` 切分思考与正文；思考增量经 `reasoning` 事件流式展示（沿用云端链路）。
- 思考仅对教练对话生效；记录解析／图片识别／周报保持非思考（jsonMode 低温任务，已有格式重试路径）。
- 采样参数本轮用 temperature 0.6 过渡；包侧暴露 topP/presencePenalty 列为后续（真机验证后再定）。

## 撞顶保护（硬需求）

1. **软子预算中止**：思考未闭合且达到子预算（建议 1024，输出上限一半）→ 主动 cancel 生成，不再空耗解码。
2. **撞顶兜底**：生成到 2048 上限时思考仍未闭合 → 判「思考未收敛」，不直接向用户报截断错误。
3. **自动降级重试**：上述两种情况都以非思考模式重发同一请求一次（ParserAgent 重试先例）；取消、内存警告、网络类错误不重试；重试仍失败保留首因与用户原文，数据不丢。
4. 被中止的思考不展示；可在工具活动记录「思考未收敛，已自动重试」。
5. 正文截断判定维持 2048 顶格，不因思考提前收紧。

## 验收

- 开关关：渲染与现网一致（空闭合 think 块），回归全绿。
- 开关开：输出含思考 → 解析出正文与思考两段；思考经 reasoning 事件上屏；jsonMode 路径先剥思考再校验。
- 子预算中止与撞顶兜底均触发非思考重试且成功出正文；重试只发生一次。
- 本地 portable 测试与 iOS CI 全绿；真机记录首字等待、思考循环发生率、格式正确率对比（开关开 vs 关）。
