# 第 20 轮：MLX Swift 独立验证

## 背景与目标

现有 llama.cpp／Metal 版本在用户设备（暂按 iPhone 15 理解）触发 L14：系统内存警告导致 App 主动停止推理。尚无真机内存曲线，不能认定 llama.cpp 有缺陷，也不能提前保证 MLX 更省内存。本轮独立验证苹果生态 MLX Swift 路线，先得到可比较的证据，再决定是否迁移生产功能。

## 范围

1. 独立源码目录、构建配置与模型存储，不修改现有聊天、课程表、健康数据、API Key 或 GGUF 文件。用户已确认独立验证 App（Milo Lab）及三屏设计。
2. 第一阶段仅短文本推理，不加载视觉编码器、不访问健康／记录库、不调用工具、不联网搜索、不自动回退云端。
3. 优先核验 Qwen3.5-2B MLX 4bit，ModelScope 默认下载源，固定 revision 与逐文件 SHA-256／字节数；不可直接复用 GGUF。若适配不成立，记录原因，不静默换模型。
4. 初始总预算 2K token，输出最多 256，输入按模型 tokenizer 实算并拒绝超限；禁用思考扩展（须按模型模板验证），每次测试独立会话，不累计历史。
5. 串行加载／生成，避免重复模型驻留；限制 MLX 缓存，关闭界面／切后台／内存警告取消并释放模型。取消须保留具体原因；不得通过关闭内存保护掩盖失败。
6. 报告记录：设备／OS、引擎与模型版本、加载耗时、首 token 延迟、输出速度、进程 phys_footprint 采样峰值、MLX active/cache/peak、可用进程内存及结束原因。区分采样峰值与严格峰值，不记录提示词和回复正文。
7. 第一阶段成功后再验证图文／工具／结构化输出；本轮不把 API 可用等同于任务质量合格。

## 验收

- 固定 3 条非敏感短文本，冷加载与连续至少 5 轮测试；覆盖停止、后台、内存警告、文件缺失／哈希不符、超限和反复加载卸载。
- 目标手机实际完成首字与完整短回复；记录性能而非预先承诺阈值。同设备相同测试文本、输入输出上限，与 llama.cpp 对比后给迁移结论。
- 下载中断保留已有完整文件；校验完成前不可推理，磁盘不足给出错误；不覆盖已有 GGUF。
- Linux 可验证纯逻辑和清单；MLX／Metal 构建与运行需 Apple 环境。CI 编译、模拟器、Mac 和 iPhone 证据分别标注。

## 交付与约束

需求、checklist、必要 UI 补稿、独立推理与诊断模块、可复现测试与构建说明。用户已追加授权提交、推送与打包；产物与构建证据记录在 validation.md，不冒充已通过真机验证。
