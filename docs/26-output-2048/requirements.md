# 第 26 轮 · 本地模型输出上限提升至 2048

## 背景与目标

用户反馈本地模型输出长度受限：本地输出为 1024 tokens 硬顶（第 19／21 轮为省内存所定，第 23 轮 16K 扩容时保留），教练课程表 JSON、周/月报等长输出场景会撞顶，触发「模型回复达到输出上限，已保留正文；未完成的计划不会执行」。

用户决定：先把本地输出上限从 1024 提升到 2048 tokens。语义理解质量与图片识别问题不在本轮范围，另行立项。

## 范围

- 唯一改动源：`LocalMLXPolicy.maximumOutput` 由 1024 改为 2048。教练本地策略（`LLMSettings.coachPolicy`）、引擎预算（`InferenceBudget`）、截断判定（`outputTokens < limit`）全部由它派生，不另行散改常量。
- 引擎预算随动：输入 + 输出 ≤ 16K；输出 2048 时输入上限 14336。超限仍明确拒绝，不静默裁剪用户输入。
- 教练本地策略随动：`outputReserve` = 2048，`inputLimit()` 由 14848 变为 13824（含 512 tokens 估算安全余量，第 23 轮约定不变）。
- 截断判定随动：生成达到 2048 才判定 truncated，未完成的计划仍不执行。
- 历史摘要请求 `min(2_048, outputReserve)` 不变，本地摘要获得完整 2048 输出空间。
- 云端请求、模型文件与下载、16K 上下文窗口、UI 展示均不变。无 UI／交互变动，不需要设计稿。

## 非功能

- 内存：MLX KV 按 16K 窗口预分配，峰值不随输出上限增长；2048 输出主要增加最坏情况解码时长。真机未验证前不得宣称稳定（第 22 轮 L14 教训）。
- 一致性：请求估算、实际 tokenizer 上限与截断判定继续引用同一策略，不单侧修改（沿用第 23 轮验收要求）。

## 验收

1. `outputLimit(4096) == 2048`；`outputLimit(1024) == 1024`（不越过上限时不抬高）；负数／零值防护不变。
2. `validate(input: 14336, output: 2048)` 通过；`14337 + 2048`、`output: 2049`、`Int.max` 均拒绝。
3. 超过旧 8K 的输入与 2048 输出组合可通过预算检查（9000 + 2048 ≤ 16384）。
4. 本地模式下 `coachPolicy.outputReserve == 2048`、`inputLimit() == 13824`、`prepare` 请求 `maxTokens == 2048`。
5. 既有回归（工具、历史整理、云端窗口）不受影响；本地 portable 测试与 iOS CI 全绿。
6. 真机单独验证：长回复生成的内存与首字等待、截断体验；未验证前不宣称已通过。
