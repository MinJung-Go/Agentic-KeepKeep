# HealthKit 侧载授权修复

## 现象与根因

Windows iLoader / Impactor 安装后显示「当前安装不支持」。旧授权失败状态持久化后隐藏重试入口；授权失败仍继续同步，覆盖原始错误。CI 的完全未签名产物不携带二进制签名中的能力声明，依赖提取声明的侧载工具无法据此申请 HealthKit。

缺少 entitlement 只能证明权限缺失，不能证明免费账号不支持。最终描述文件和签名是否获准，需要设备验证。

## 修复

- [x] 首页与设置对旧签名错误保留「重新授权并同步」。
- [x] 文案区分上次授权结果与当前安装状态，去除免费账号必然不支持的说法。
- [x] 授权失败停止同步；后台的页面刷新不能覆盖错误；授权期间避免重复请求。
- [x] 增加旧失败状态重试成功、授权失败不继续同步的回归测试。
- [x] IPA 打包前对 App / widget 进行 ad-hoc 签名并嵌入各自权限声明；签名后逐项读取校验。
- [x] CI 在模拟器产物上验证签名脚本；手动工作流支持 build_ipa。
- [x] 构建号更新为 0.4.2 (4)。
- [x] 授权修复 macOS CI 构建、单测和归档验证：`34fac33`，运行 [34827934900](https://github.com/MinJung-Go/Agentic-KeepKeep/actions/runs/34827934900) 成功。
- [ ] Impactor 重新签名后的 HealthKit 真机授权和运动导入验证。

## 安装验证

1. 保留旧 App，先导出 JSON 备份。
2. 使用新 IPA，经 Impactor 同一 Apple ID、相同实际 Bundle ID 覆盖安装。不要仅注册主程序包，也不要注入插件。
3. 设置 → HealthKit → 重新授权并同步；允许读取体能训练等数据。
4. 若仍失败，提供新版错误；需进一步检查最终签名/描述文件，不能用 ad-hoc 声明代替 Apple 授权。
5. 确认最近 30 天已有运动记录能导入且重复同步不重复插入。

本轮不增加后台自动同步或单次训练热量字段；先恢复现有读取能力。
